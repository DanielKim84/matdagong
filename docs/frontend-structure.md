# 프런트엔드 구조

현재 A안 브랜드 원본·캐릭터의 위치와 파일별 용도는 [브랜드 정리](../frontend/public/assets/brand/README.md)를 참고합니다. 브랜드 폴더에는 폐기한 비교 시안을 남기지 않습니다.

React 화면, 서버 API 호출, 탭·브라우저에 잠시 남기는 값을 분리합니다. 사용자 기록은 맛다공 서버(장소·커뮤니티 모듈)에 저장합니다.

```text
index.html → src/main.tsx → app/signIn.ts (로그인·가입 확인) → app/startupView.tsx (소개·가입 또는 앱)
                                                           → app/App.tsx (AppData 제공) → screens/<영역>/*
화면 → services/*.ts → services/http.ts(apiRequest) → 맛다공 서버(4845) → 장소·커뮤니티 모듈
화면 → services/auth.ts → 공통 인증 서버(/auth-api)
화면 → components/*, hooks/*, models/*, utils/*
```

하단 탭(발견·피드·내 지도·맛객·나)은 각 탭의 첫 화면에서만 보이고, 나머지 화면은 상단 바의 뒤로 버튼을 씁니다. 가운데 내 지도는 열린 노트와 책갈피 모양을 다른 탭보다 큰 둥근 사각형 배경에 담습니다. 비선택 상태에서도 중립색 테두리와 배경으로 구분하고, 선택 상태에서는 코랄 테두리·은은한 코랄 배경·강조 그림자로 활성 상태를 표현합니다. 아이콘과 탭 이름은 겹치지 않습니다.

## 데이터와 화면 경계

로그인은 `dagong-auth`를 사용합니다. 맛다공 가입 상태 확인·가입은 인증 서버(`/auth-api`)를, 나머지 API는 맛다공 서버(`/api`)를 호출합니다. 모든 API 호출은 `services/http.ts`의 `apiRequest`를 거치며, 로그인이 만료되면 `main.tsx`가 등록한 처리기가 현재 주소를 기억하고 `app/signIn.ts`로 다시 로그인합니다. 이때 등록 화면은 작성 중인 입력을 `registerDraft.ts`로 보관합니다.

어느 데이터가 어느 서비스에 있는지와 API 경로는 [도메인 및 API 경계](api-boundaries.md)의 [주요 API](api-boundaries.md#주요-api)·[탈퇴](api-boundaries.md#탈퇴)를 기준으로 합니다. 화면 쪽에서 알아 둘 점만 적습니다.

- 장소 목록에는 사용자가 기록하거나 저장한 장소만 나옵니다(개발용 샘플 장소·맛객은 없앴고, 장소가 하나도 없어도 화면은 빈 상태로 그립니다). 기록·하트·다녀온 곳·별로였던 곳·최근 본 장소·빠른 저장·제보는 장소 모듈, 프로필·취향·구독·포인트·태그 제안·알림·맛객 신고는 커뮤니티 모듈에 계정별로 저장됩니다.
- 장소 응답의 기록에는 작성자 사진·캐릭터가 없습니다. `services/places`가 빈 사진·1번 캐릭터로 받아 두고 `app/enrichPlaces`가 커뮤니티 프로필(이름·사진·배경·점수)로 채우며, 프로필을 찾지 못한 맛객은 기본 캐릭터로 보입니다.
- 맛객 신고는 맛객 프로필과 맛집 기록 카드의 `TasterReportButton`(`screens/tasters`)에서 보냅니다. 내가 신고한(확인 전) 맛객은 신고 버튼을 "신고했어요 · 확인 중"으로 막고, 신고가 쌓여 가려진 내 프로필은 나 화면 맨 위에 안내합니다.
- 같은 종류의 다른 기기에서 로그인해 이 기기 로그인이 끝났는지는 맛다공 서버(`ActiveLoginFilter`)가 API 요청마다 확인해 401로 막고(답은 토큰별 30초 기억), `useSignedInDeviceCheck`는 앱으로 돌아올 때 가입 상태를 한 번 물어 마지막 접속 시각을 남깁니다.
- 맛다공 탈퇴(설정 맨 아래)는 장소 → 커뮤니티 → 공통 로그인의 맛다공 가입 순서로 지우고 로그아웃합니다. 셋 다 다시 불러도 괜찮습니다.
- 비공개 기록 사진은 서명된 `/media/...?exp=&sig=` 주소로 내려오므로 주소가 만료될 수 있습니다.
- 알림 수신 설정에서 끈 종류의 알림은 서버가 만들지 않습니다.
- 실제 결제 처리는 연결되지 않았고 유료 구독은 개발용 완료 흐름입니다.

배경 사진을 올리지 않은 맛객은 `utils/profileMedia.ts`가 계정 ID로 고른 기본 배경(`default-cover:N`, 그림은 `public/assets/content/covers/default-covers.png`·`content/covers/default-cover-5.png`)을, 사진이 없는 맛객은 계정별 기본 캐릭터를 씁니다.

브라우저 저장소는 화면 편의용 값에만 쓰고, 키와 읽기·쓰기는 모두 `utils/storage.ts`(`STORAGE_KEYS`)를 거칩니다.

- sessionStorage: 로그인 토큰·PKCE 값·돌아갈 주소(`app/signIn.ts`, `http.ts`), 등록 입력 보관(`registerDraft.ts`)과 다른 화면이 기록 화면으로 넘기는 일회성 장소, 내 지도 검색에서 고른 카카오 가게(`place/kakaoPlaceDetail.ts`, 새로 고쳐도 상세가 열리게), 발견 화면의 필터·시트 높이(`discoverStorage.ts`)
- localStorage: 계정별 소개 화면 완료 표시, 피드 스토리에서 이미 본 기록(`feedRecords.ts`)

맛객 프로필의 공개 분야·태그와 개인 추천 취향은 별도로 저장합니다. 추천 취향의 제외 조건은 다른 사용자에게 공개하지 않습니다. 태그 사전(`GET /api/v1/taste-tags`)과 태그 제안은 태그마다 `tagGroup`(8개 분류) 하나로 나눕니다. 매장 이용 태그는 `VISIT` 분류이고, 나머지 일곱 분류가 취향 태그입니다.

| 분류(`tag_group`) | 화면 이름     | 한 분류에서 고르는 수 | 보이는 분야                                         |
| ----------------- | ------------- | --------------------- | --------------------------------------------------- |
| `CUISINE`         | 음식 종류     | 10                    | 식당                                                |
| `TASTE`           | 맛·메뉴       | 5                     | 식당                                                |
| `CAFE`            | 카페 종류     | 5                     | 카페·디저트                                         |
| `DESSERT`         | 디저트·빵     | 10                    | 카페·디저트                                         |
| `TRAVEL`          | 여행·드라이브 | 5                     | 모두                                                |
| `MOOD`            | 뷰·분위기     | 10                    | 모두                                                |
| `OCCASION`        | 이럴 때       | 5                     | 모두                                                |
| `VISIT`           | 매장 이용     | 5                     | 기록의 매장 이용 정보, 추천 취향의 피하고 싶은 조건 |

- 이름·순서·한도·분야별 분류는 `models/tasteTags.ts` 한 곳에 두고 서버 `TasteTagGroup`(`maxSelections`)·`FoodFocus.allowedGroups`와 같게 맞춥니다. 분야가 "둘 다"면 VISIT을 뺀 일곱 분류이고, 기록하기의 장소 분야(음식점·카페)도 같은 묶음을 씁니다.
- 매장 이용 16개 이름은 `models/place.ts`의 `VISIT_CONDITIONS`(하나만 고르는 묶음은 `VISIT_CONDITION_GROUPS`)에도 있고, 커뮤니티 DB의 VISIT 태그와 반드시 같아야 합니다. `app/enrichPlaces`가 내 제외 조건과 기록의 매장 이용 정보를 이름으로 비교하기 때문입니다. 피하고 싶은 조건으로 고를 수 있는 것은 그중 `AVOIDABLE_VISIT_CONDITIONS` 6개입니다(화면에서만 거름).
- 기록을 저장할 때 `tagGroups`는 태그 사전에서 정하고, 사전에 없는 이름(빠진 옛 태그)은 보내지 않습니다. 탭 저장소에 남은 기록 입력(`registerDraft`)·발견 필터(`discoverStorage`)의 옛 이름도 사전을 기준으로 뺍니다.

## 수정할 때 지킬 점

- 서버 API는 `services/`의 함수로 호출하고, 새 API 함수도 `apiRequest`를 거치게 합니다. 화면에서 `fetch`를 직접 쓰지 않습니다(정적 지역 파일도 `services/regions.ts`).
- 화면 사이에 값을 넘기거나 보관하는 저장소 키는 `utils/storage.ts`의 `STORAGE_KEYS`에 둡니다. 사용자 기록을 브라우저 저장소에 새로 저장하지 않습니다.
- 서비스 데이터베이스를 다른 서비스가 직접 조회하지 않습니다.
- 반복해서 쓰는 UI는 `components/`, 여러 화면이 쓰는 훅은 `hooks/`, 화면과 무관한 계산은 `utils/`, 자료형·도메인 상수는 `models/`에 두고(같은 일을 영역 안에서 다시 만들지 않음), 현재 기본 화면 전용 배치는 `styles/screens/<영역>.css`에 둡니다. 클래스는 `r-<영역>-` 접두사를 쓰고, 색·글꼴·반경은 테마 토큰만 씁니다.
- 스타일은 화면별 파일과 공통 UI 파일에 응집도 있게 둡니다. 실제 책임이 나뉘는 경우에만 파일을 분리하고, cascade 순서와 찾기 쉬운 구성을 우선합니다. 줄 수만 맞추기 위한 CSS 분리는 하지 않습니다.
- 파일이나 주요 흐름에 설명이 필요한 경우에만 주석을 두고, 코드에서 바로 알 수 있는 내용을 반복하지 않습니다.

## 원본과 빌드 결과

`frontend/public/`은 직접 관리하는 정적 원본입니다. `frontend/dist/`는 빌드가 소스 번들과 public 파일을 복사해 만드는 배포 출력이므로 두 폴더에 같은 이미지가 보이는 것은 정상이며, 이미지는 public에서만 관리합니다. dist는 Git 제외 대상이고 개발 서버도 사용하지 않으므로 지워도 다음 빌드에서 다시 생성됩니다. dist 안의 파일을 직접 편집하거나 원본처럼 보관하지 않습니다. `docs/ui/current-design.md`는 현재 기본 화면 동작 기준, `docs/ui/theming.md`는 기본 테마와 테마 추가 방법입니다. `docs/ui/proposals/`는 화면 시안과 전달용 자료를 보관하며 앱 실행 코드나 현재 동작 명세가 아닙니다.

지도 공유 자료형과 표시 계약은 `models/map.ts`, 내 위치 요청은 `hooks/useMyLocation.ts`에서 관리합니다. 내 위치는 최신 요청만 반영하며 화면을 떠난 뒤 응답은 버립니다. 위치 권한 상태는 `hooks/useLocationPermission.ts`(바탕은 `utils/geo`의 `watchLocationPermission`)로 보고, 권한이 켜지면 `useMyLocation`이 바로 위치를 잡습니다. 공유 Neon DB 사용 기준에 따라 옛 로컬 Docker 초기화 구성은 제거했습니다.
