# 현재 UI 기준

브랜드는 열린 원형 접시와 분리된 대각선 포크를 코랄 단색으로 표현한 A안을 사용합니다. 앱 아이콘은 쨍한 코랄과 입체감이 있는 버전, 작은 심볼은 평면형을 사용합니다. 자산·캐릭터·소개판의 기준 위치는 [브랜드 정리](../../frontend/public/assets/brand/README.md)를 따릅니다. 이 저장소의 기본 앱 디자인은 현재 코드이며 `frontend/src/styles/screens/`에서 관리합니다. [UI 시안 자료](proposals/README.md)는 별도 문서용 제안이므로 현재 화면의 완료 상태를 뜻하지 않습니다.

맛다공은 모바일 중심으로 설계하고, 넓은 화면에서도 앱 화면 폭을 유지합니다. 화면은 `frontend/src/screens/`에, 공통 인터랙션과 그림은 `frontend/src/components/`에 둡니다. 색상과 공통 레이아웃은 `frontend/src/styles/`에서 관리합니다.

기본 인트로(`#intro`)는 첫 가입과 설정의 “맛다공 앱 소개”에서 공통으로 쓰는 5장 슬라이드입니다. 보드 03·04-01 대신 사용자가 고른 H안 내용과 구도를 지금 앱 모양으로 다시 그린 안을 씁니다(2026-11-24, 기준 그림 `docs/ui/proposals/intro/H-flow-applied.png`(원본 H안에서 쪽 표시를 지우고 로고·뒤로 버튼·버튼만 바꾼 그림)). 진짜 후기(이 리뷰, 광고일까? 협찬일까?) → 입맛 맞는 맛객 → 가볼수록 쌓이는 믿음 → 지도에는 진짜 기록만 → 기록하고 구독 수익으로(유료 구독·정산은 준비 중) 순서입니다. 쪽마다 왼쪽 정렬 큰 제목(강조 낱말은 코랄)과 설명 → 위아래가 흰 바탕에 녹는 화면 폭 사진(H안과 같은 사진·구도, 파일 비율대로 폭에 맞춰 확대하지 않음) → 사진 아래쪽에 걸친 앱 모양 예시 카드(`IntroCards`: 광고 의심(회색 사람 표시)/실제 방문, 맛객 카드, 왼쪽 타임라인이 있는 방문 줄과 코랄 방패 신뢰 상자, 가게와 두 줄 방문 기록 수, 연한 바탕 안 흰 줄 두 개의 공개 범위와 기록→구독자→구독 수익(막대그래프) 흐름 · 그 아래 준비 중 안내) → 점 다섯 개(지금 쪽은 길쭉한 코랄) → 버튼입니다. 첫 쪽은 맨 위 자기 줄에 입체 가로 로고(`brand-logo.png`)와 "건너뛰기 · 다음"(건너뛰기는 바로 시작), 2쪽부터 뒤로 버튼과 "다음", 마지막 쪽은 "맛다공 시작하기"이고, 밀어서·화살표 키로도 넘깁니다. 별점은 앱 규칙대로 두지 않고("한식 · 350m · 연남동"), 비공개 기록은 앱 이름 "나만 보기"입니다. 실행은 `frontend/src/screens/onboarding/IntroScreen.tsx`·`IntroCards.tsx`, 표현 규칙은 `frontend/src/styles/screens/onboarding.css`가 기준입니다.

2026-11-18 제작한 [전체 화면 UI 시안](proposals/README.md)은 최신 브랜드를 적용한 검토용 자료입니다. 18개 보드·72개 화면/주요 상태와 동작 설명을 담고 있으며, [HTML 열람본](proposals/index.html)과 [PDF 전달본](proposals/matdagong-uiux-handoff.pdf)을 함께 제공합니다. 브랜드 A 기본 테마, 지도 중심 발견, 5개 균등 하단 탭, 나 탭 사진 모음, 맛집 상세의 정보 패널·추천 이유 높이는 반영되어 있습니다. 나머지 화면은 현재 앱에 적용 완료되었다는 뜻이 아니며, 실제 동작은 현재 코드가 기준입니다.

## 제품 흐름

서비스의 중심은 별점 목록을 늘리는 것이 아니라, 실제로 다녀온 맛객의 기록을 보고 내 입맛에 맞는 사람을 구독해 음식 선택의 고민을 줄이는 것입니다. 주요 흐름은 다음과 같습니다.

1. 발견(지도)과 피드에서 맛집 및 맛객의 기록을 둘러봅니다.
2. 장소 상세에서 맛객별 추천 이유와 메뉴·방문 정보를 살펴봅니다.
3. 취향이 맞는 맛객을 구독하고, 구독한 맛객의 기록을 이어서 확인합니다.
4. 맛객은 본인의 분야·활동 지역·기록을 공개 프로필로 소개합니다.
5. 내 장소는 어디서나 세 갈래로 부릅니다: **공유 중**(다른 맛객에게도 보이는 공개 내 기록) · **가본 곳**(다녀왔지만 공유하지 않은 곳 — 나만 보기 기록과 기록 없이 빠른 저장한 곳·기록을 지운 곳) · **가볼 곳**(하트, 코랄). 공유 중·가본 곳·구독 안 한 맛객 핀 색은 테마 토큰 `--shared-*` · `--visited-*` · `--other-*`(`theme/themes/default.css`, 공유 중 스카이, 가본 곳과 구독 안 한 맛객은 같은 쨍한 탠저린) 한 곳에서 정합니다. 내 지도 칩·마커·수·목록 이름표, 내 맛집 모음 칩, 나 탭 사진 모음이 같은 이름과 색을 씁니다(`screens/mymap/myMapModel.ts`의 MyPlaceCategory).

닉네임은 맛객끼리 겹치지 않습니다. 가입 1단계와 프로필 편집에서 입력하는 동안 겹치는지 바로 알려 주고(겹치면 다음·저장을 막음), 저장할 때 서버가 한 번 더 확인합니다.

가입 1~3단계(보드 04-02~04-04)는 머리 그림 없이 흰 화면 위쪽에 뒤로 버튼과 번호 단계(①—②—③, `StepProgress`)만 둡니다(1단계 뒤로는 서비스 소개로). 닉네임 칸은 로그인한 계정의 별명으로 미리 채우되, 네이버처럼 가린 아이디("hosu\*\*\*\*")가 오면 빈칸으로 시작합니다. 가입 1단계("프로필을 만들어주세요.")는 가운데 큰 프로필 사진(`SignupPhotoField`, 코랄 카메라 배지) → 카카오·네이버 사진을 받았으면 "소셜 프로필 사진 사용" 카드(오른쪽 스위치, 테두리 없는 고르기 줄: "소셜 사진으로 사용하기" / 다른 사진을 고르면 "고른 사진으로 사용하기" / "기본 사진으로 변경하기"와 작은 기본 캐릭터) → 닉네임(칸 안 오른쪽 글자 수, 쓸 수 있으면 초록 체크와 "사용 가능한 닉네임이에요.") → 다음 순서입니다. 연락용 이메일은 따로 받지 않고 로그인한 계정의 것을 씁니다. 카카오·네이버 사진은 그 제공자에 사진 제공을 동의했고 기본 사진이 아닐 때 받아 그 사진으로 시작합니다. 가입을 마칠 때 고른 파일은 올리고, 소셜 사진은 커뮤니티 서버가 내려받아 저장합니다(이미 사진이 있으면 그대로, 실패해도 가입은 마침). 사진 주소는 dagong-auth 가입 상태의 `profileImageUrl`이고, 서버는 카카오·네이버 사진 서버(https)만 받습니다.

맛객 프로필의 공개 스타일과 사용자의 비공개 추천 취향은 서로 다른 설정입니다. 광고 장소와 광고 마커는 두지 않습니다. 지도와 목록은 맛객 기록만 보여 줍니다.

## 경험 신뢰 (취향은 시작, 신뢰는 경험으로)

태그로 맞춘 취향 %는 출발점이고, 같은 맛집을 직접 다녀와 입맛이 맞았던 경험이 쌓이면 그 맛객과의 **신뢰 %**가 됩니다. 신뢰가 높은 맛객이 기록한 곳은 처음 가는 동네에서도 믿고 갈 수 있게 하고, 아직 구독하지 않은 맛객이라도 지도에서 눈에 띄게 해 구독으로 이어지게 하는 것이 목적입니다.

- **인정한 맛집**: 내 기록(공개·나만 보기 모두). 가볼 곳 하트는 아직 가 보지 않았으므로, 빠른 저장만 한 다녀온 곳은 입맛을 남기지 않았으므로 세지 않습니다.
- **엇갈린 맛집**: 한쪽은 인정했고 다른 쪽은 "다녀왔는데 별로였어요"로 남긴 맛집. 맛없던 곳은 대개 아무것도 남기지 않으므로 세지 않습니다.
- 신뢰는 **서로 같은 값**입니다(나와 A가 함께 인정한 곳이 많으면 A에게도 내가 믿을 만한 맛객이 됩니다). 나만 보기 기록도 세지만, 화면에는 퍼센트만 보여 주고 어떤 맛집이 겹쳤는지는 보여 주지 않습니다.
- **신뢰 %** = 경험 일치 50% + 같은 맛집 태그 일치 30% + 취향 일치 20%.
  - 경험 일치: 함께 인정한 곳 ÷ (함께 인정한 곳 + 엇갈린 곳)
  - 태그 일치: 둘 다 기록한 맛집에서 "어떤 곳이었나요?"에 고른 태그·매장 정보가 겹친 정도의 평균. 비교할 기록이 없으면 이 항목을 빼고 나머지 비중으로 계산합니다(취향 태그가 없을 때도 같음).
  - 계산은 커뮤니티 모듈 `TasteTrust` 한 곳에서 하고, 재료(인정·엇갈림·태그 일치)는 장소 모듈 `TasteTrustService`가 셉니다(커뮤니티 모듈은 `PlaceDirectory.trustStats`로 받음). 항목·비중을 바꿀 때는 이 문서도 함께 고칩니다.
- **등급**: 함께 다녀온 맛집(인정 + 엇갈림)이 10곳 이상일 때만 붙습니다. 10곳 미만은 "알아 가는 중"입니다.
  - 등급은 잘게 나누지 않습니다. 80% 이상이면 "믿고 가는 맛객" 하나뿐입니다.
  - 10% 미만 "입맛이 다른 편"(구독을 막지 않도록 지도에는 표시하지 않고, 프로필·맛객 고르기에만 흐리게 보여 줌)
- **하트 누르기**: 하트는 간단한 켜고 끄기입니다(`app/useLikeChoice.ts`, `LikeChoiceSheet.tsx`). 내 기록이 있는 곳은 이미 내 맛집이라 하트를 쓰지 않습니다.

  | 지금 상태        | 누르면                                                                                    |
  | ---------------- | ----------------------------------------------------------------------------------------- |
  | 하트 없음        | 바로 가볼 곳으로 저장                                                                     |
  | 가볼 곳(찬 하트) | "가볼 곳에서 빼기" 시트(보드 10-02, 고르기 줄 `.r-option`): 가볼 곳에서 빼기 · 별로였어요 |
  - 예전 "다녀왔어요 · 입맛에 맞았어요" 하트는 V12에서 다녀온 곳으로 옮긴 뒤 없앴습니다(장소 V18).
  - **별로였어요**는 직접 다녀온 곳만 고를 수 있습니다. 들른 근거(다녀온 곳·이미 남긴 별로였던 곳)가 있거나 지금 위치가 가게 1km 안이면 남기고, 아니면 "직접 다녀온 곳만 별로였다고 남길 수 있어요"를 알립니다. 서버도 근거 또는 보낸 기기 위치로 다시 확인합니다([직접 다녀온 곳 확인](../api-boundaries.md#직접-다녀온-곳-확인)).
  - 별로였어요를 고르면 하트가 사라지고 그 맛집을 **지도에서 뺍니다**: 발견(지도·카드·목록·검색)과 내 지도에 마커가 없습니다. 피드·스토리·맛객 프로필에는 그대로 보이고, 맛집 상세 이름 옆에 회색 "별로였어요" 뱃지가 붙습니다. 이 맛집을 인정한 맛객과의 경험 신뢰에는 엇갈림으로 셉니다.
  - 잘못 골랐다면 나 탭의 "별로였던 곳"(`#disliked`)이나 맛집 상세의 "되돌리기"로 되돌립니다(엇갈림에서도 빠짐).
  - **가볼 곳에서 빼기**는 하트만 지우고 신뢰에는 아무 영향이 없으며, 발견에 다시 보입니다.

- **보이는 곳**: 맛객 옆 점수는 신뢰가 있으면 "신뢰 N%"(믿고 가는 맛객이면 별을 붙인 노란 칩), 없으면 "취향 N%"입니다(`components/TasteScore`).
  - 지도 핀은 새 종류를 만들지 않고, 오른쪽 위 표식 하나로 구분합니다. 구독 중인 신뢰 맛객은 하트 표식의 하트만 같은 코랄색 별로 바꾸고, 구독하지 않은 신뢰 맛객은 주황 바탕 흰 별 표식을 붙입니다.
  - 발견의 마커 안내 순서는 구독 중인 맛객 → 구독 중인 신뢰 맛객 → 구독하지 않은 맛객 → 구독하지 않은 신뢰 맛객입니다.
  - 발견 목록·맛집 상세 맛객 고르기·맛객 추천은 믿고 가는 맛객을 먼저 보여 주고, 맛객 프로필은 신뢰 %·등급을 취향 % 위에 보여 줍니다.

## 시각 요소 (브랜드 A 적용 1차)

- 기본 테마는 흰 바탕·차콜 글자·선명한 코랄(`#EF365B`)이고 글꼴은 아래 "글꼴"의 Matdagong입니다. 2026-11-23부터 [화면 보드](proposals/boards)를 기준으로 화면을 바꾸고 있습니다(화면 바탕 흰색, 카드는 그림자 대신 옅은 테두리, 사진 목록은 카드 없이 옅은 선으로 나눈 줄). 선택 상태는 연한 코랄 바탕과 진한 코랄 글자로 표시하며, 태그 분류·방문 상태 등 의미가 다른 색상은 각 역할을 유지합니다.

- 소개(#intro): 다섯 장을 옆으로 넘기는 이야기. 구성·사진·글꼴은 위 첫 문단(기본 인트로)이 기준입니다.
- 넓은 화면(700px 이상)에서는 앱이 둥근 틀 안에 그려지고, 하단 탭과 하단 버튼 줄도 그 틀 바닥에 붙습니다. 가로 목록은 PC에서 마우스로 조금만 끌어도 다음 카드로 부드럽게 넘어갑니다.
- **글꼴**: 앱 전체가 한 글꼴 가족 "Matdagong"(`frontend/src/theme/fonts.css`)을 씁니다. 기준은 갤럭시 "Mong수박씨"이고(웹에 넣을 수 없는 유료 플립폰트), 보통 굵기(500 이하)는 티머니 둥근바람, 굵은 글씨(600 이상)는 주아로 그려집니다. 화면 CSS는 글꼴 이름을 직접 쓰지 않고 `var(--font-body)`·`var(--font-display)`와 font-weight만 정합니다.
- 색과 제목 글꼴은 테마 패키지(`frontend/src/theme`)에서 정합니다. 현재는 기본 테마만 등록되어 있으며, 새 테마가 필요해지면 토큰 파일을 추가하고 등록하는 방법은 [테마 구조](theming.md)를 참고합니다.
- 기본 아바타는 계정별로 배정한 맛다공 캐릭터를 사용합니다.

## 취향 태그

태그 사전은 8개 분류, 107개 태그입니다(이름·한도는 [프런트엔드 구조 · 데이터와 화면 경계](../frontend-structure.md#데이터와-화면-경계)). 분류마다 아이콘과 색을 하나로 정해(`components/GroupIcon`) 태그 고르기 · 이런 곳이에요 · 맛객 프로필 취향 탭 · 발견 필터에서 똑같이 씁니다.

| 분류          | 아이콘 · 색    |
| ------------- | -------------- |
| 음식 종류     | 포크 · 노랑    |
| 맛·메뉴       | 반짝이 · 초록  |
| 카페 종류     | 커피 · 갈색    |
| 디저트·빵     | 케이크 · 베리  |
| 여행·드라이브 | 자동차 · 파랑  |
| 뷰·분위기     | 산과 해 · 청록 |
| 이럴 때       | 두 사람 · 코랄 |
| 매장 이용     | 가게 · 회청색  |

- **태그 고르기**(`components/TasteTagPicker`: 가입 취향 단계, 프로필 편집의 추천 취향·공개 스타일·피하고 싶은 조건, 기록하기. 분류가 하나뿐이면 제목 없이 칩만)는 고른 분야의 분류만 보여 줍니다(식당 · 카페·디저트는 다섯 분류, 둘 다는 일곱 분류). 가입 2단계("어떤 맛집을 찾으시나요?")는 "찾는 분야"(식당 · 카페 · 둘 다, 아이콘과 이름을 한 줄에 둔 낮은 카드 `FoodFocusPicker`, 둘 다는 포크+컵, 고르면 연한 코랄. 프로필 편집은 같은 세 가지를 작은 칩 줄 `variant="chips"`로)를 먼저 고르고, 분류마다 "음식 종류 2/10" 제목과 # 없는 넓은 알약 칩을 시트 없이 펼치며 분류 사이를 가는 선으로 나눕니다(`TasteTagPicker inline`). 펼치는 분류는 음식 종류·맛·메뉴·카페 종류·디저트·빵 중 그 분야 것과 이럴 때이고, 여행·드라이브 · 뷰·분위기는 나중에 골라도 되는 덤이라 "더 고르기" 아래에 분류 줄만 두고 누르면 시트에서 고릅니다. 고르지 않아도 "다음"으로 갑니다. 가입 3단계(보드 04-04, `SignupMatchStep`)는 "추천 맛객 N명"과 정렬(취향 높은순 · 구독자 많은순), 맛객 줄(얼굴 · 이름과 오른쪽 "취향 N%" 또는 "인기" · 가본 곳·구독자 수 · 회색 글자 태그 · 오른쪽 체크 상자), 아래 "선택한 맛객 구독하기 (N명)" 체크와 "맛다공 시작하기"입니다. 무료 구독은 한 번에 한 명이라 보드와 달리 한 명만 고릅니다. 취향이 겹치는 맛객을 취향 % 순으로 먼저, 취향을 안 골랐거나 모자라면 구독자·기록이 많은 맛객으로 채웁니다(`loadRecommendations`). 구독 체크를 끄거나 아무도 고르지 않으면 구독 없이 시작합니다. 보드의 "가볼 곳 N곳"은 서버가 맛객별 수를 주지 않아 아직 넣지 않았습니다.
- 분류마다 흰 줄 하나: 분류 아이콘 · 이름 · (고른 태그가 없으면) 짧은 안내 또는 (있으면) 고른 태그 전부 · 오른쪽 "선택 N/한도" · 꺾쇠. 고른 태그가 있는 줄은 테두리가 연한 코랄입니다. 맨 위에 "분류를 눌러 골라요. 꼭 맞는 것만 골라도 돼요."를 둡니다.
- 줄을 누르면 아래에서 그 분류의 시트가 올라와 태그를 **모두** 보여 줍니다(접어 둔 칩 없음). 제목 아래 안내와 "선택 N/한도", 칩(`r-chip` + 코랄 `#`, 고르면 연한 코랄 바탕·진한 코랄 글씨, 줄을 바꿔 감김), 바닥에 붙은 "완료" 버튼. 고르는 즉시 반영되고 완료·바깥 누르기·Esc로 닫습니다.
- 분류가 하나뿐인 곳(피하고 싶은 조건)은 시트 없이 흰 카드 안에 칩을 바로 둡니다.
- 한 분류에서 한도(10 또는 5)를 채우면 고르지 않은 칩을 흐리게 막고 "N개를 모두 골랐어요. 바꾸려면 고른 태그를 하나 빼 주세요."를 짧게 알립니다.
- 피하고 싶은 조건은 매장 이용 중 주차 공간 협소 · 주차 불가 · 웨이팅 있는 곳 · 브레이크타임 있음 · 노키즈존 · 불친절 경험만 고를 수 있습니다.
- 태그 제안(`TasteTagRequestScreen`, 보드 17-04)은 전체 화면입니다: 음식 사진 띠 위 "새로운 태그를 제안해 주세요." · 분류 칩(아이콘 없는 글자 칩, 매장 이용 제외) · 태그명 · 설명(선택, 0/100) · "태그 제안하기" · 내 제안(분류 알약 · 태그명 · 검토 중 노랑/적용 완료 초록/미반영 회색 알약). 프로필 편집의 추천 취향에서 엽니다(기록하기 3단계에는 제안 버튼을 두지 않음).
