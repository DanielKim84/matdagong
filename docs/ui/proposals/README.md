# 맛다공 UI/UX 인수인계 시안

기준일: 2026-11-18. 앱 화면은 이 보드대로 맞췄고, 보드와 다르게 둔 곳은 [보드와 다른 점](board-gaps.md)에 적습니다.

## 프로젝트 내 보관 위치

이 폴더는 앱 런타임에서 읽지 않는 화면 시안과 전달 자료를 보관합니다. UI 규칙은 [현재 UI 기준](../current-design.md)과 [테마 문서](../theming.md)에 있고, 앱의 현재 동작은 코드가 기준입니다. 이 폴더는 규칙 문서나 백업이 아닙니다. 다운로드 폴더의 파일에 의존하지 않습니다.

- [HTML 열람본](index.html): 화면 보드 확대·검색과 화면별 설명
- [앱 소개 기준 그림 · H안 수정본](intro/H-flow-applied.png)([설명](intro/README.md)): 앱 서비스 소개(IntroScreen)의 기준(2026-11-24). 원본 H안 보드(intro/H-flow.png)에서 쪽 표시(1/5)를 지우고, 1쪽 왼쪽 위 입체 맛다공 로고, 2쪽부터 뒤로 버튼, 쨍한 코랄 버튼(1쪽 건너뛰기 · 다음, 2~4쪽 다음, 5쪽 맛다공 시작하기)만 바꾼 그림. 사진·배경·카드는 원본 그대로
- [PDF 전달본](matdagong-uiux-handoff.pdf): 전체 43페이지
- 전체 자료 ZIP(`matdagong-uiux-handoff.zip`): 이 폴더의 문서·18개 보드와 현재 브랜드 자산 사본. 120MB라 저장소에는 올리지 않고 필요할 때 아래 `package.py`로 다시 만듭니다
- [화면별 설계 목록](screens.json), [제작 요청과 보정 내역](prompts.json), [검증 기록](verification.json)
- [현재 브랜드 원본과 사용 기준](../../../frontend/public/assets/brand/README.md): 아이콘·로고·배너·브랜드 사용 보드·캐릭터 소개판

브랜드 원본은 위 자산 폴더에서 관리하고, 이 폴더에는 화면 설계 자료를 모읍니다. ZIP은 전달 시점의 사본이며 수정 기준은 프로젝트의 원본 파일입니다.

## 보는 순서

1. `index.html`을 열어 18개 화면 보드를 확대하고 화면별 설명을 확인합니다.
2. `matdagong-uiux-handoff.pdf`는 회의·전달·인쇄용입니다.
3. `screens.json`은 72개 화면/상태의 ID·목적·동작 규칙·현재 코드 위치입니다.
4. `boards/`의 PNG는 기획서나 디자인 문서에 그대로 넣을 수 있는 고해상도 화면 보드입니다.
5. `prompts.json`은 내장 image_gen 제작 요청입니다. `build.py`와 `template.html`은 HTML/PDF를 다시 만드는 문서 생성기입니다. 코드 확인 링크는 저장소 안에서 열 때 사용합니다.

## 범위와 확정 상태

- 브랜드 A의 현재 아이콘·한글/영문 로고·배너를 기준으로 구성했습니다.
- 18개 묶음 × 4개 화면 = 72개 화면/주요 상태를 보여줍니다. 탭·시트·진행 단계는 별도 URL이 없는 경우도 있습니다.
- 동일한 긴 화면은 상단/하단 또는 단계별로 나누었습니다. 보드는 문서용 화면 시안이며 실제 앱을 캡처한 스크린샷이 아닙니다.
- 기능·정책은 현재 코드와 `docs/ui/current-design.md`를 기준으로 확인했습니다. 사진 중심 발견 목록은 검토용 제안일 뿐, 현재 발견 첫 화면은 지도와 하단 목록 패널입니다.
- 실제 사용자·장소·인물 사진·점수·수량은 문서용 예시입니다. 이미지 속 작은 문구보다 화면 설명의 정확한 동작 규칙을 기준으로 구현합니다.
- 5개 하단 탭, 공통 계정/서비스 구분, 저장·방문·기록의 의미, 공개/비공개, 맛객별 기록 경계는 유지합니다.
- 유료 구독은 개발 흐름이며 실제 결제·정산·교환·후원은 연결되지 않았습니다. 정책 문서는 법률 검토 전 초안입니다.
- 기존 앱 코드를 재설계로 교체하거나 DB·인증 정책을 수정하지 않았습니다.

## 적용 진행 상태

이 시안은 최신 브랜드 A를 기준으로 정리한 검토·인수인계 자료이고, 앱 화면은 이 보드대로 맞췄습니다. 기능을 지키려고 보드와 다르게 둔 곳과 아직 비워 둔 칸은 [보드와 다른 점](board-gaps.md)에 적습니다. 실제 동작은 [UI 기준 문서](../current-design.md)와 코드가 기준입니다.

## 다음 담당자에게

먼저 PDF의 설계 원칙·확정/제안 구분을 읽고, 화면 ID를 기준으로 의견을 남깁니다. 실제 구현 전에는 390px 화면과 긴 문구, 빈 데이터, 저장 실패, 접근성, 사진·개인정보 노출 범위를 검증합니다. 지도 위치·내비게이션·인증은 실제 기기에서도 확인해야 합니다.

브랜드 사용 기준은 `frontend/public/assets/brand/README.md`, 로고 사용 보드는 `brand-identity.png`, 캐릭터·굿즈 소개판은 `brand-guide.png`입니다. 두 자료는 목적이 다르므로 모두 유지합니다.

## 문서 다시 만들기

Python 3에서 reportlab, Pillow, pypdf가 있는 환경으로 실행합니다. 기본 글꼴은 Windows 맑은 고딕입니다. 이 저장소의 현재 브랜드 자산과 `screens.json`, `boards/`를 읽습니다.

```powershell
python docs/ui/proposals/build.py
python docs/ui/proposals/package.py
```
