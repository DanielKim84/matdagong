# 포인트 원장 기준

현재 커뮤니티 서비스는 `user_point_history`에 포인트 변동을 기록하고 `GET /api/v1/points`에서 로그인 사용자의 잔액과 최근 내역을 조회합니다. 잔액은 적립·사용·조정 거래의 합계이며, 거래마다 계정 UUID와 원장 UUID를 사용합니다. 같은 계정의 같은 업무 참조 키는 중복 저장하지 않습니다.

현재 API는 조회만 제공합니다. 구독을 완료해도 포인트가 자동 지급되지는 않습니다. 지급·사용·환불을 연결할 때는 서버가 정책과 완료된 업무 이벤트를 확인하고, 원장 행을 추가하는 방식으로 처리해야 합니다. 기존 거래를 덮어쓰거나 삭제해 잔액을 맞추지 않습니다.

정산이나 교환을 출시하기 전에는 최소한 다음을 정해야 합니다.

- 어떤 이벤트에 얼마를 적립할지, 취소·환불 시 어떻게 상계할지
- 중복 요청을 막을 멱등성 키와 원장 참조 규칙
- 잔액 부족·동시 사용을 막는 트랜잭션 처리
- 관리자 조정 권한과 사유 기록, 감사 이력
- 상품권·현금 교환을 포함한 사업 및 규제 검토

현재 포인트 원장은 커뮤니티 DB에 있으며, 독립적인 포인트 서비스를 이미 운영하는 것으로 간주하지 않습니다. 트래픽·정산 책임이 분리될 때 서비스 경계를 다시 판단합니다.
